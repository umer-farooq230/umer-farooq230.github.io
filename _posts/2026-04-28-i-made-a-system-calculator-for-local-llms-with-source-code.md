<p>I coded the solution of my own problem</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*xhEQQWNB7F81Wqu_" /><figcaption>Photo by <a href="https://unsplash.com/@solenfeyissa?utm_source=medium&amp;utm_medium=referral">Solen Feyissa</a> on <a href="https://unsplash.com?utm_source=medium&amp;utm_medium=referral">Unsplash</a></figcaption></figure><p>Ever since I have discovered local LLMs from huggingface and Ollama, I have downloaded and ran many of the models, but each time the same problem occurred</p><h3>The Problem</h3><p>Every time I wanted to run a model, My process looked like this:</p><ol><li>Find a model</li><li>Get excited about its benchmarks</li><li>Scroll reddit for reviews and system reqs</li><li>Ask GPT</li><li>Try anyway</li></ol><p>… and it still crashes after 3 prompts.</p><p>The question was same every time. “What should be my system’s specifications to run this smooothly?” but my approach was wrong</p><h3><strong>The Solution</strong></h3><p>I made a simple web app which ask you two simple things about your system. <strong>GPU (VRAM) and RAM. </strong>And other things like Number of Tokens and Quantization</p><p>and It tells you</p><ul><li>Which models you can run</li><li>Which ones might run but within limits</li><li>Which ones will not just run</li></ul><p>That’s it. No Overengineering. Thinking in “System” rather than “Substance”</p><h3>How It Works</h3><p>The app estimates how much VRAM a model needs based on its parameter size, then adjusts that based on quantization.</p><p>A 7B model in full precision is very different from the same model in 4-bit, so that reduction is applied directly. It also includes context length in the calculation, since longer token windows increase memory usage and are often the hidden reason models fail to run.</p><p>Once it has this estimate, it compares it with your available VRAM and gives a practical result. Based on the headroom I have added different categories</p><ul><li><strong>SAFE</strong>: Uses ≤85% GPU VRAM</li><li><strong>TIGHT: </strong>Fits in GPU VRAM (tight, up to 100%)</li><li><strong>OFFLOAD:</strong> Requires CPU/RAM offloading (slower)</li><li><strong>WON’T RUN</strong>: Exceeds GPU + system RAM</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/0*UkQfYDOoGdI_ZdnC" /><figcaption>Photo by <a href="https://unsplash.com/@galka_nz?utm_source=medium&amp;utm_medium=referral">Galina Nelyubova</a> on <a href="https://unsplash.com?utm_source=medium&amp;utm_medium=referral">Unsplash</a></figcaption></figure><h3>Thinking In Systems</h3><p>As I am becoming more mature with coding and taking Infrastructure seriously rather than adding more features, my perspective about developing is also changing</p><p>Simple solutions always beats complex engineering. This is how old me would have thought about the solution.</p><p>Make an AI wrapper -&gt; give RAG docs -&gt; Track the system reqs -&gt; Give Solution</p><p>But when I stopped thinking about the hype of training a model and started thinking about building a system, things changed, for good.</p><h4><strong>Code:</strong></h4><p>You can check the <a href="https://github.com/umer-farooq230/Can-My-GPU-Run-It"><strong>Repo here</strong></a></p><p>Would love to see your creativity here modifying the code</p><p>Feel free to connect with me on <a href="https://www.linkedin.com/in/umer-farooq230/">Linkedin</a>, <a href="https://github.com/umer-farooq230/">Github</a> or <a href="http://umerfarooq230@gmail.com">Email</a>.
